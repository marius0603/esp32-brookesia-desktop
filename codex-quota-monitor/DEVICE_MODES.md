# 自动息屏与定时勿扰

需要固件 `0.8.3-s3.15`。

## 自动息屏

入口：**设置 → 显示 → 自动息屏**，默认开启。连续 10 分钟没有触摸时关闭 AMOLED 显示。
轻触屏幕唤醒，首次接触及其释放不点击底层按钮。中间实体电源键保持原有开关机行为。
息屏保留应用、Wi-Fi 和音频播放；天气动画停止绘制，唤醒后最多 5 秒恢复。
这是显示息屏，不是关机或深度睡眠，后台任务仍运行。

## 深度睡眠（手动需 s3.18，时长选择需 s3.19）

从 s3.19 起，入口位于 **设置 → 显示** 页前部。“自动深度睡眠”提供 **关闭、10 分钟、20 分钟、30 分钟、1 小时、2 小时、4 小时**，默认关闭，选择后自动保存。
选择时间后，从最后一次触摸开始计时；正在播放听书、连接/录音/思考/播报语音时暂缓，音频活动结束后重新等待完整时长。
听书暂停、语音助手连接就绪但没有对话时可以正常计时。天气刷新与电脑额度同步不作为触摸活动。
唤醒后重新开始所选时长，避免刚唤醒又立即休眠；原有 10 分钟自动息屏独立保留。

**立即深度睡眠** 按钮仍保留，确认提示后开始，不需要等待闲置时间。
先关闭除桌面外的应用，停止听书/语音连接，检查设置保存，再关闭屏幕与 Wi-Fi，进入 ESP32-S3 Deep-sleep。
准备期间暂不接收触摸，也不允许启动新的音频任务；准备失败会取消深睡，恢复显示并在诊断状态记录错误。

唤醒源配置为触摸中断 GPIO11 和自定义按键 GPIO18 的低电平。
中间 PWR 键仍由电源管理芯片控制，保持原有开关机行为；不把它当作直接连接 MCU 的短按唤醒键。
唤醒会重新启动桌面与网络，保留已保存的设置和小智绑定，不恢复应用在 RAM 中的运行现场。
触摸芯片、PMU 以及部分外设继续供电；这是主控深睡，不代表整板断电，整机休眠电流尚未测量。

需要先烧录新版应用分区，再增量更新已有 Settings 的显示资源：

```powershell
# 位于 codex-quota-monitor，先停止占用串口的额度同步
.\stop.ps1
.venv\Scripts\python.exe tools/deploy_deep_sleep_settings.py ..
# 必须重启开发板再打开设置；仅关闭/重开设置不能清除开机预加载的 DOM。
.venv\Scripts\python.exe tools/verify_deep_sleep.py
```

部署只更新 `display.json`，先把原文件备份到 SD，再以校验过的 USB 传输替换。
Settings 启用了开机 DOM 预加载，因此部署后必须先重启设备，新入口才会显示；关闭应用不会清除这份缓存。
`DeviceModes.TestDeepSleep` 使用相同流程，但额外提供 20 秒恢复计时器；测试期间不要触摸屏幕或按唤醒键。测试脚本核对真实定时唤醒原因、RTC 入睡计数和原有设置。
`DeviceModes.DeepSleepNow` 和屏幕按钮不启用计时器；`GetState.deep_sleep` 可读取入睡请求、最近唤醒原因与外部唤醒 GPIO 位图。
`DeviceModes.SetAutoDeepSleep` 的 `Minutes` 接受 0、10、20、30、60、120、240；0 表示关闭。
`GetState` 同时返回所选分钟数、音频忙状态、剩余闲置秒数及设置是否已加载。
`tools/verify_auto_deep_sleep.py` 验证全部档位与非法输入，并通过临时 5 秒闲置计时和 20 秒恢复计时器验证真实自动入睡、音频暂缓及跨唤醒保存；测试不触摸屏幕，完成后恢复原时长。
测试加速只存在于明确调用的诊断方法中，不保存为用户选项。分钟/小时边界、毫秒计时回绕和并发触摸快照在 `tests/idle_deep_sleep_static.cpp` 编译检查。
测试结束并确认设备已唤醒后，恢复 `.\start.ps1`。

2026-10-22 实机确认：重启加载新版设置后入口可见，用户通过屏幕确认进入深睡并轻触唤醒。
读取到 `wake_cause=3`（EXT1）、`wake_pins=2048`（GPIO11），网络恢复为 `Connected`，10 分钟自动息屏仍开启。
这是深睡后正常重新启动桌面，不保留 RAM 中的应用运行现场。

硬件引脚参见[微雪板卡资料](https://docs.waveshare.net/ESP32-S3-Touch-AMOLED-2.16/)，
深睡及 EXT1 唤醒行为参见[ESP-IDF 6.0.2 文档](https://docs.espressif.com/projects/esp-idf/en/v6.0.2/esp32s3/api-reference/system/sleep_modes.html)。

## 定时勿扰

入口：**设置 → 声音 → 定时勿扰**。显示设置中不再提供勿扰开关。
使用开始、结束时间的小时和分钟选择器设置每天的静音时段，自动保存。
数字框与弹出列表统一使用奶油色背景、棕色大号数字，选中数字以下划线标识；不显示缺失字形的箭头。
默认时间为 **22:00–07:00**，定时开关默认关闭，由用户开启。

- 按北京时间运行，支持跨午夜时段。
- 包含开始时刻，不包含结束时刻；到结束时间恢复之前的音量。
- 起止时间相同时为全天静音。
- 未完成联网校时显示等待提示，校时完成后按时间段运行。
- 静音覆盖听书和语音助手等板载音频输出；期间调整音量不会覆盖原音量。
- 结束后仍遵守儿童音量上限和声音页面原有的普通静音设置。

设置保存在独立 NVS 命名空间，重启保留；不修改家长 PIN、Wi-Fi 和小智凭据。
NVS 的读取、写入均在现有内部内存后台任务中执行，避免外部内存任务栈在 Flash 操作时触发断言。
定时检查与重力感应共用 100ms 轮询任务，不额外分配任务栈，跨时间边界不反复写 Flash。

## 更新与验证

已有设备完成应用分区固件更新后部署界面资源：

```powershell
.venv\Scripts\python.exe tools/deploy_device_modes.py ..
```

脚本逐个备份旧天气、显示设置和声音设置文件到 SD，再经传输校验替换。重启刷新资源。
不修改分区表、不清除 NVS。自动验证：

```powershell
.venv\Scripts\python.exe tools/verify_quiet_hours.py
```

验证真实时钟跨过静音结束点后自动恢复音量；代码编译检查覆盖跨午夜、起止边界和全天时段。
早先 s3.14 已实际验证：599 秒仍未息屏，600 秒进入息屏，主机计时 600.12 秒；
天气动画在息屏后停止，在维护命令唤醒后恢复。首次触摸唤醒需要实体屏幕确认。

维护服务 DeviceModes 提供 GetState、SetAutoSleep、SetQuietHours(Enabled, StartMinute, EndMinute)、SleepNow、Wake。
时间参数是 0–1439 的整数分钟。保留 SetDoNotDisturb 作为维护用立即静音接口，普通用户使用声音页面的定时开关。
GetWeatherLayers 读取图层颜色、大小、实际透明度和时间选择器的数字、字体、配色，用于界面诊断；不读取 PIN 或其他输入内容。
