# 离线命令词

固件 s3.22 使用固定的 ESP-SR 2.4.5（c43077feefa033950e1a208f2d3190a9d28905b0），WakeNet9 `wn9_nihaoxiaozhi_tts` + 中文 MultiNet5 Q8 `mn5q8_cn`。模型共 2,494,541 字节，放在 `/sdcard/offline-voice/models/`，保留现有 Flash 分区。

这是识别试验版。最终候选的数字回归已执行讲故事、暂停、继续、下一篇及两类音量操作；“小声点”需要重说一次，“还剩几分钟”连续两次漏识别，测试随后停止，不能宣称八类语句全部通过。上一候选曾完成八类及三条无关语句检查，该结果不代替最终候选的准确率验证。真实童声准确率尚未测量。

“设置 → 声音 → 离线语音”开启后，先说“你好小智”，稍停约一秒，再说指令；按需加载会有短暂准备时间。每次成功执行后重新等待唤醒。识别窗口约 12 秒，MultiNet 自身超时也会结束本次监听。听书 0.2.1 页面另有大号“点一下说话 · 离线”按钮，可直接开启命令窗口，不要求先念唤醒词。

本机合成语音检查中，原始说法“暂停 / 继续 / 继续播放 / 大声点 / 晚安 / 还有多久”尚未稳定命中，当前优先使用“暂停故事 / 还要听 / 大声一点 / 我要睡觉了 / 还剩几分钟”；这几条原始说法仍保留为可尝试别名。数字验证报告会记录实际使用的句子，不将替代表达的结果当作原短语的通过结果。

针对主要使用者 1–3 岁，加入“故事 / 听故事、停停、还要听、换一个、大一点、小一点、睡觉觉、还多久”等短说法。这个年龄的发音变异较大，建议家长陪同，不能承诺通用模型可识别每个孩子。

普通息屏仍监听；真正深度睡眠停止监听，需要触摸或实体键唤醒。

| 命令 | 行为 |
| --- | --- |
| 讲故事 | 打开听书，继续当前故事或播放 SD 中第一篇 |
| 暂停故事 / 停一下 | 暂停当前故事 |
| 还要听 | 继续当前故事 |
| 下一篇 / 换一个故事 | 播放下一篇，末尾返回第一篇 |
| 大声一点 | 音量加 10%，尊重儿童音量上限 |
| 小声点 / 小声一点 | 音量减 10% |
| 我要睡觉了 / 睡觉觉 | 停止故事，允许时轻声播晚安，然后息屏 |
| 还剩几分钟 | 中文播报睡眠定时剩余分钟；未设定时会说明 |

同一意图加入常用长短说法及少量 shi/si、xu/su、eng/en 发音变体；暂停、继续、晚安和剩余时间使用 0.45 分数下限，启动/切换故事与音量调整使用 0.62 下限；不同意图至少相差 0.15。低于阈值或两个不同意图分数接近时不执行，保留窗口让孩子重说。唤醒后暂时降低故事 PCM 音量。该实现是通用中文模型加别名规则，未针对某个孩子训练；儿童识别率、距离和噪声容错需要使用真实童声测量，不能由数字音频测试推断。

本模块不引用 HTTP、WebSocket、录音上传或云模型接口，不保存麦克风录音或转写。输入只在 RAM 中处理。待机只保留 AFE 与 WakeNet；唤醒或点击说话后才加载 MultiNet，识别完成或超时立即释放，加载命令模型前在 LVGL 锁内临时停用解码图片缓存，并清理可释放条目；命令结束或超时先释放模型，再恢复默认 1MiB 缓存。界面对象和整屏缓冲保留，避免图片缓存挤占时钟与听书解码所需内存。内存不足时拒绝加载并显示状态，保留当前界面。关闭开关会停止麦克风采集、释放 AFE 和识别模型；共享的底层音频接口保留，避免反复创建 I2S 通道。连接小智时先释放这些资源，在线助手关闭后恢复。在线助手仍遵循原有云对话流程；离线功能不会自动发起在线对话。

采集与推理使用两个独立任务，避免音频输入和模型处理互相阻塞。AFE 缓冲保留 80 帧，覆盖 VAD 语音历史及命令模型加载时的短暂积压；状态接口同时报告采集/推理进度和两任务栈余量。MultiNet 使用连续 AFE 输出帧，不把已经处理过的 VAD 起始缓存重复拼接；与基于 VAD 截断上传的云识别路径分开。

最终候选直接使用 AFE 提供的帧，检查帧长度后交给 MultiNet，去掉额外拼接缓冲；不在采集任务仍运行时重置 AFE 环形缓冲。连续命令测试中未再出现内存不足或重启，采样到的最低 PSRAM 约 445KB，识别结束和超时后命令模型已释放、默认图片缓存已恢复。这是本轮资源检查结果，不是长时间稳定性或儿童识别率承诺。

时钟与命令窗口共存检查已通过：实际跨过分钟边界，数字更新并完成八帧翻页，最低剩余 PSRAM 319,012 字节；窗口结束恢复 1MiB 缓存。内存余量仍有限，不能仅因资源文件移到 SD 就视为释放了运行内存。

前端使用单麦克风与播放参考（32 位双声道先转换为 16 位，板载 RM 重排为 AFE MR）、WebRTC VAD 和回声处理。听书统一输出 16kHz、16 位双声道（左右复制相同声音以匹配 32 位采样槽），让不同采样率故事与麦克风共享 I2S 时钟；位置依旧按源音频帧计算。提示语音从 SD 读取，本机 Windows Huihui Desktop 预先合成，不需要运行时网络 TTS。

## 构建、部署与测试

1. 按仓库构建流程安装固定依赖并构建 s3.22，使用 `flash_brookesia.py --app-only` 保留已有数据。
2. 停止电脑端串口采集，运行 `tools/deploy_offline_voice.py --repo <仓库目录>`：核对固定依赖中的六个模型文件哈希，上传 SD 模型、中文提示和数字测试片段；备份并更新声音设置页。首次部署结束开启离线语音。
3. 重启一次更新原生 Settings 的预加载页面，检查声音页开关。
4. `tools/verify_offline_voice.py` 检查数字音频推理、命令执行、开关释放、助手本地麦克风接管和断网行为；每条允许重说一次，遗漏与每次得分写入本机报告，不将复述通过当作首遍成功；在线服务器对话需另行实测。`TestAction` 只测试路由；`TestPhrase` 使用固定本地数字音频（编号 9–11 为无关语句），均不等同于真实麦克风/童声验证。

`--resources-only` 单独检查断网、三条无关语句、模型反复开关和麦克风接管；报告明确标记 `scope: resources_only`，不覆盖八类命令准确率，也不会覆盖完整语句回归的失败报告。

最终候选的资源专项检查已通过：Wi-Fi 停止时三条无关语句未触发命令；三次完整加载在“模型已加载、图片缓存已停用”的同一阶段分别剩余 449,624 / 438,052 / 437,336 字节 PSRAM，结束后均释放模型并恢复缓存；在线助手本地录音回放能接管麦克风，结束后恢复离线待机。待机截图缓存会额外占用约 333KB，比较重载是否泄漏时必须统一缓存阶段。

七档自动深睡、非法时长、播放暂缓和真实闲置深睡/RTC 唤醒检查通过；唤醒后单次深睡定时保持关闭，离线麦克风和唤醒模型恢复，待机剩余 PSRAM 约 2.9MB。检查采用临时 5 秒闲置阈值与 20 秒恢复定时，并非逐档等待完整时长。原有 10 分钟息屏及用户音量、勿扰设置已保留。

首次开机开关默认为关闭；已经部署并保存开启后会恢复。模型缺失、哈希不符或内存不足时不打开麦克风，保留桌面和串口排查能力。不能把麦克风驻留识别的功耗当作深睡功耗。

`tools/build_offline_voice_prompts.ps1 -Output resources/offline-voice` 可在中文 Windows 上重建 47 个剩余时间提示和 11 个数字测试片段（八条命令和三条无关语句）。音频为 16kHz、16-bit、单声道裸 PCM；哈希位于 `resources/offline-voice/audio.json`。模型二进制由固定的官方组件依赖取得，仓库只保存版本及哈希。

连续本地命令帧的处理参考乐鑫 [ESP-BOX 本地命令示例](https://github.com/espressif/esp-box/blob/master/examples/factory_demo/main/app/app_sr.c)。`tools/verify_clock_offline.py` 会让真实命令窗口跨过时钟换分钟，检查缓存释放/恢复期间的数字更新。
