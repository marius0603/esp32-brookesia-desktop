# 去除图标外层底色（s3.41 / 图标缓存1.1.0）

用户指出的是整张图标外多出的一圈方框或底色。桌面图标尺寸本身正确：旧缓存已预处理为92×92，与显示槽位匹配，桌面样式也已关闭边框与背景。根因是旧RGB565导出器将原图透明区域合成成`#fff1dc`，在壁纸上形成不透明方块。

新缓存保留原PNG的透明通道，导出92×92 RGB565A8/RLE，保留彩色圆角底板、主体与原轮廓。九枚Q版图标及轻学习更新，电子宠物保持不变；壁纸和应用界面不变。图标从原96×96源图缩放，不再从64×64限色回退图放大。

十枚解压缓存合计253920字节，旧版169280字节，固定增加84640字节（约82.7KiB），占8MiB PSRAM约1%。启动预载后复用，不在滑动时读取SD或重新解码。透明混合本身仍有绘制成本，不能仅用缓存大小推断实际流畅度。

当前固件的自定义预载器原先仅接受RGB565压缩图，即使LVGL支持RGB565A8也会在注册应用时拒绝新图标。s3.41的第九份补丁扩展格式校验及解压后长度校验，兼容RGB565和RGB565A8。**必须先安装s3.41，再部署透明缓存**；部署器会拒绝较早固件。若先部署到旧固件导致初始化失败，需要通过已验证私有备份和应用分区更新器安装s3.41以恢复，不能依赖此时已经停止的USB服务做文件恢复。

生成及部署：

```powershell
python tools/build_launcher_cache.py
python codex-quota-monitor/tools/package_launcher_cache.py
# 先本地完整备份，再只更新s3.41应用分区；原有NVS/LittleFS/SD保持
python codex-quota-monitor/tools/deploy_transparent_icons.py --port COM5
```

安装器将资源存放在SD的`/sdcard/themes/launcher-alpha-v1-时间戳/`，逐文件SHA256核对，逐项备份并更新图标索引。这样不挤占当前有限的LittleFS空闲空间；SD需保留在设备中。重启加载缓存后，正常使用期间不反复访问图标文件。每次安装使用新目录，避免FAT上覆写已存在的提交目标失败；保留原索引和旧缓存，回退可在兼容固件下运行`--restore <本机transparent-icons备份目录>`，随后重启。

验证范围：导出时独立解码RLE并逐字节核对RGB和透明通道；原生九份补丁顺序应用并重建50份源码，与实编目录匹配。运行日志与完整备份只保存在私有runtime目录。

2026-11-02同一s3.41固件、同一Q版桌面冷启动对比，每种资源各六次强制整屏重绘：旧图标中位133595µs，透明图标139272.5µs，约增加4.2%。最终PSRAM剩余2958692字节（约2.82MiB），内部RAM81779字节（约79.9KiB）；十枚图标预载及全部12个应用注册成功。测试不代表实际滑动帧率或长时无泄漏保证；用户已现场确认外层底色消失、左右滑动顺畅。
