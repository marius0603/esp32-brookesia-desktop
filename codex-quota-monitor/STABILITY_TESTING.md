# 两小时实机稳定性测试

2026-11-17后续：已针对大块连续分配风险部署s3.69/迷宫0.1.8，分块缓存与40次打开、第十关短测通过，详见[修复记录](MEMORY_RECOVERY.md)。以下保留11月16日原始失败结论；本次尚未重新跑满连续两小时。

这项测试检查已安装固件和 SD 应用的连续运行，不安装新固件、不改写应用程序或资源文件。实际测试结果见本文末尾；运行中的 `passed: false` 表示尚未完成，不能提前当作通过或失败。

## 覆盖范围

四个阶段各 30 分钟：

| 阶段 | 工作负载 | 重点记录 |
| --- | --- | --- |
| 儿歌 | 顺序连续播放 | 自然播到结尾后的自动换曲、PCM 输出、内存 |
| 摇篮曲 | 随机播放，开启真实 15 分钟定时 | 最后 2 分钟淡出、定时结束后保持停止 |
| 听书 | 顺序连续播放 | 自动换章、输出任务、内存 |
| 应用切换 | 天气、时钟、额度、电子宠物、迷宫，每次停留约 30 秒 | 打开关闭与资源回收、空闲时反复启停蓝牙 |

每约 5 秒采样 CPU、内部堆、PSRAM、蓝牙 DMA 余量和拒绝计数、播放器状态与 PCM 诊断。固件时钟必须持续向前，不能把重启后的新运行拼接成一次连续测试。

应用切换段遇到启动错误时，记录应用名与错误，卸载该次失败界面，再继续其他应用以完成覆盖；最终结论仍是失败。`open_attempts`、成功 `opens` 与 `open_failures` 分开计数，不把跳过失败应用当成成功。

蓝牙先在播放器空闲时启动，再运行音频。当前固件会主动拒绝播放或录音过程中**新启动**蓝牙；测试保留这项保护，不能把这种拒绝当成内存分配失败。广告启动与资源检查不等于手机实际配对、遥控命令验收。

播放音量暂设为零，解码和 PCM 输出照常执行。这验证数据链路，不是听感、响度或喇叭声学检查。电台网络流、离线识别和小智云端往返不在本轮范围。

## 运行与恢复

需要设备 USB 供电、串口在线、SD 插好、30 篇故事、20 首儿歌和 10 首摇篮曲。测试不会绕过家长验证；需要家长先退出儿童模式、解锁，并结束正在进行的播放、录音和睡眠定时。停止其他占用串口的额度同步程序。

在仓库根目录，使用已安装 `pyserial` 的 Python：

```powershell
python codex-quota-monitor/tools/verify_audio_soak.py --port COM5 --minutes 120
```

仅补测应用切换段时使用 `--workload apps --minutes 30`。它生成独立记录，只能判定这一段，不会将先前中断的整轮改成通过，也不等于连续两小时验收。

测试暂时关闭自动深度睡眠，保留原有自动息屏设置。开始前备份音量、深睡时长、两类播放模式、速度和相关书签文件到本机 `codex-quota-monitor/runtime/audio-soak-时间/`。结束或正常捕获异常后，停止测试播放器和测试开启的蓝牙、取消测试定时，并恢复这些偏好；不会修改 PIN。Windows 版本通过进程级电源请求在测试期间保持主机唤醒，结束即释放，不改变系统电源计划；其他平台需自行保持主机唤醒。

需要提前结束时，在仓库根目录创建：

```powershell
New-Item -ItemType File -Path codex-quota-monitor/runtime/audio-soak-stop.request
```

等待状态变成 `stopped_by_request` 并确认 `preferences_restored`，再移除这一个停止请求文件。不要直接结束 Python 或拔线；强制中断时可能无法恢复，需依据本机 `recovery.json` 核对并恢复原设置。测试后重新启动原额度同步程序。

原始采样、设置备份和分析结果只留在被 Git 忽略的 `runtime`，不得上传。

独立分析要求跑满时长、四阶段覆盖、设置恢复、自然换曲、睡眠淡出及结束均有证据；采样不足、两分钟以上观测空窗、设备时钟回退、PCM 断粮和新增蓝牙内存拒绝均不能通过。若自动换曲失效，驱动会先记录问题再显式切到下一首维持压力；这样的恢复不算自动换曲成功。

状态文件使用临时文件替换，遇到 Windows 读者短暂拒绝删除共享时，最多重试 3 秒，始终保留上一份完整 JSON；持续权限错误仍失败。回归包含真实 Windows 句柄占用下的复现与恢复，以及永久错误不能被吞掉的检查：

```powershell
python -m unittest discover -s codex-quota-monitor/tests -p test_soak_status_write.py -v
```

测试后还需读回版本、曲库、偏好和原书签，核对显示错误计数与清理后的内存。最低可用堆值是本轮余量，不能单凭它承诺没有泄漏或永不内存不足。
