# 部署验证

## 2026-11-19 主界面拖动时复用图标绘制（s3.78）

- 用 LVGL 快照在桌面空闲时缓存每个按钮的图标和文字。拖动和吸附时绘制缓存，原控件继续接收触摸，停止滚动时恢复原控件的绘制和整行收尾刷新。桌面主题或图标变化会让缓存重新建立。在 App 加载资源前释放桌面的像素数据，并在启动结束前暂停重建。内存不足时沿用原绘制路径。
- 同一台 COM5、同一版固件，通过原生分页容器跑相同的横向位移。两组各 72 次刷新，计时包括原生绘制和数据发送。

| 帧间隔 | 缓存关闭 | 缓存开启 |
| --- | ---: | ---: |
| 中位数 | 165.8 ms | 111.4 ms |
| P95 | 192.2 ms | 121.0 ms |

- 实测缓存共 735 KiB，空闲时首次建立耗时约 250 ms。曾测试过整条图标栏共 1.06 MiB 的单块缓存，从天气页返回后的 PSRAM 碎片使其无法重建。按按钮分别分配后，从天气页返回可以重建。随后又将释放提前到 App 加载前，最终固件通过天气和翻页时钟的开关及返回检查。
- 听书与持续翻页并发时 PCM 输出仍推进，但出现缓冲耗尽。同版交替对照中，静置约 4 秒无耗尽；缓存关闭的两轮分别记录 26、28 次，开启的两轮均为 17 次。每轮脚本移动 24 步，耗时不同，不能据此断定日常播放已无卡顿。已核对 16 个应用注册、应用分区烧录读回以及分区外 Flash 校验。23 份补丁按清单重建并匹配构建源码。
- 同步 USB 翻页压测曾在冷启动阶段出现超时。诊断现由 LVGL 任务逐帧运行，采样可在下一帧之前交还 GUI 锁。本轮数据来自脚本位移，手指实际跟随、松手吸附、图标点击与黑线仍待目视复测。持续 60 fps 尚未达到。可用 `DeviceModes.ProfileLauncher` 的 `Cached` 参数启动两种模式，再用 `GetLauncherProfile` 读取结果。

## 2026-11-19 天气局部绘制优化（s3.77）

- 天气前台在 PSRAM 用 450 KiB 缓存已绘制的 RGB565 像素。LVGL 只重画变动区域，发送前从缓存补齐两侧像素，CO5300 继续接收完整行。缓存未就绪或申请失败时仍整行绘制，退出天气页后释放缓存。
- 同一台 COM5 设备使用晴天白天动效采样，两个版本各 26 次局部刷新。排除强制整屏样本。

| 指标 | s3.76 | s3.77 |
| --- | ---: | ---: |
| 单次局部刷新耗时中位数 | 36.3 ms | 20.7 ms |
| 单次局部刷新耗时 P95 | 42.5 ms | 24.0 ms |
| LVGL 重画像素数中位数 | 43,200 | 7,920 |

- 在听书进行中打开天气页时暂缓建立缓存，沿用整行绘制。听书停止后自动补齐缓存，动效恢复局部绘制。缓存预热后再启动听书，短测未耗尽 PCM 缓冲。反复打开和关闭天气页时，s3.76 对照版和 s3.77 修订版均有缓冲耗尽，播放切页稳定性仍待排查。
- 晴天动效每 250 ms 更新，实测耗时未达到 60 fps 所需的 16.7 ms 预算。实机测量覆盖晴天场景，黑线和其他天气的面板目视检查仍待完成。
- 21 项天气脚本回归通过。22 份补丁可从固定上游顺序重建并匹配实际构建源码。应用分区刷写后读回校验通过，分区外数据校验一致。

## 2026-11-19 CO5300 显示传输优化（s3.76）

- 参考 [PopkaStudio Halo](https://github.com/PopaSpinka/PopkaStudio/tree/6e6e3b6efc73cf6f2e132715e03569e890cad588/lib/Halo) 的分块并行思路。80 MHz QSPI 的每段整行传输从 4 行增至 8 行。DMA 发送一段时，CPU 填充另一块 7.5 KiB 暂存区。只有一段像素在途，等待上一段完成后才更新 CO5300 地址窗口。暂存分配不足时可退回较小的缓冲区或单缓冲。保留双行对齐、桌面边缘像素缓存和天气的整行更新。
- 在同一台 COM5 设备上记录每组耗时中位数。整屏项目由 USB 诊断触发；天气样本为应用自身动画的最近一次刷新，排除了切换后的第一次采样。

| 场景 | s3.75 | s3.76 |
| --- | ---: | ---: |
| 桌面强制整屏，各 9 次 | 208.9 ms | 190.8 ms |
| 从应用返回桌面后强制整屏，各 3 次 | 209.9 ms | 186.3 ms |
| 听书播放时桌面强制整屏，各 15 次 | 231.8 ms | 212.5 ms |
| 天气局部刷新，各 11 个样本 | 49.9 ms | 36.9 ms |

- 新版开机初期另测得桌面整屏中位数 127.7 ms。表中采用热机复测。热机整屏的 LVGL 刷屏回调中位数为 49.4 ms，其余时间包含绘制和调度。持续 60 fps 尚未达成；本轮未做手动翻页或面板撕裂的目视验收。
- 16 个应用均已注册，翻页时钟和天气可打开并退出。听书并发刷屏时 PCM 输出持续推进，未记录缓冲耗尽。其间最大输出间隔约 10.2 ms。结束后内部 RAM 最大连续空闲块 42 KiB，PSRAM 剩余约 2.49 MiB，未记录到分配失败。
- 经典音乐广播在供数充足的一轮连续刷屏中输出持续推进。交替静置和刷屏也都出现了供数不足及缓冲耗尽，最长输出间隔约 6.5 秒。未验证持续稳定播放，苏州台、Naps 的历史停顿和断网恢复结论仍待改善。
- 完整 Flash 备份通过读回校验。实机更新仅写入应用分区，分区外区域校验一致。21 份补丁从固定上游顺序重建 66 份文件，与构建源码一致。

## 2026-11-18 桌面翻页黑线修复（s3.70）

- 实屏复现了随桌面翻页区域移动的左侧竖线。调整容器边距和缩窄后的对齐窗口均有残留。每帧整行绘制可清除竖线，但拖动变慢。只在翻页结束整行重绘可清除静止画面的竖线，拖动时仍可见。
- LVGL 继续局部绘制。针对覆盖桌面翻页区域的面板写入，显示驱动从 PSRAM 缓存补齐两侧像素，在原有 4 KiB DMA 暂存区拼出完整行。缓存为 120 KiB，只有在补齐所需的行边缘数据齐全时才扩宽写入。翻页结束仍会触发整行重绘。
- 实屏验收覆盖慢拖、快速左右翻页与点击图标。拖动和停稳时均无黑线，滑动与点击正常。设备观测到 16 次新增整行 DMA 写入和 8 次翻页结束重绘。验收后内部 RAM 的最大连续空闲块为 58 KiB，PSRAM 可用约 2.47 MiB，最大连续空闲块约 2.06 MiB，未记录到分配失败。
- 19 个补丁可从固定上游版本顺序重建并匹配构建目录。应用分区烧录后校验通过，分区外数据校验一致，16 个应用均已注册。
