# 壁纸定时微移

需要固件 `0.8.3-s3.16` 和带微移边距的奶油手绘壁纸描述。

桌面可见且屏幕点亮时，每 60 秒切换一次位置，围绕中心上下左右最多偏移 3 像素。
九个位置循环。桌面使用提前生成的 486×486 RGB565 位图，坐标始终处于 -6 到 0 之间，保持屏幕边缘完整。
仅壁纸移动，桌面图标、文字、按钮和触摸区域保持原位置。

打开应用或息屏时暂停；返回桌面或唤醒后重新等待 60 秒，避免积累后突然连续移动。
复用桌面已有的状态栏定时器，不增加任务栈、不重复加载壁纸、不写入 Flash/NVS。
这个功能只分散壁纸固定细节的位置，不能代替自动息屏，也不能消除所有 AMOLED 老化风险。

原始 JPEG 保留在主题中；运行时采用 LVGL 原生 RLE 位图，约 89KB，解压后的像素约 461KiB。
Brookesia 在加载文件时一次性解压为 RGB565 像素，保存在已有图片资源缓存中，再按原生比例绘制，避免 JPEG 按块解码和实时缩放拖慢应用切换。
当前构建没有开启 LVGL 的整图文件加载，因此压缩文件由 Brookesia 解析，并作为普通像素描述传给 LVGL。
SD 存在时优先读取 SD 上的同一位图，缺卡时使用 Flash 副本，最后才回退到原 JPEG。
首次构建通过 `CONFIG_LV_USE_RLE=y` 启用解码，并用本地源码变体修正当前 LVGL/GCC 的格式诊断兼容问题。

### s3.17 的整屏合成

桌面位图缓存之外，显示输出改用一个位于 PSRAM 的 480×480 RGB565 绘制缓冲，
先完成整块无效区域的绘制，再交给原有 SPI/HAL 路径发送。
整屏刷新从 15 个软件绘制条带变为 1 个；SPI 驱动仍按 9,600 字节的小 DMA 事务传输，
保留原有回调、互斥锁、颜色顺序和旋转映射。
相比原有两个 32 行内部缓冲，PSRAM 增加约 450KiB，内部 RAM 释放约 60KiB。
应用内的小区域更新仍使用局部刷新，不强制每次绘制整屏。

`DeviceModes.ProfileRefresh` 在 LVGL 锁内记录真实整屏刷新耗时与输出条带数量，
`Force=true` 时使当前画面失效并执行一次同步刷新。诊断只操作显示，不改变应用或用户设置。

```powershell
.venv\Scripts\python.exe tools/profile_display_refresh.py --port COM5 --label current
```

该脚本比较桌面及从时钟、天气、额度返回后的整屏刷新，将测量保存在本机 runtime。
USB 命令往返和应用启动时间不能代表像素实际绘制时间，因此另用此测量和实体观察判断刷新效果。

## 已有设备更新

先更新应用分区固件，再停止电脑端额度采集器，执行：

```powershell
# 位于 codex-quota-monitor
.\stop.ps1
.venv\Scripts\python.exe tools/deploy_wallpaper_shift.py --port COM5
```

脚本校验并上传主题中的位图，在 SD 可用时同步一份，再备份当前背景描述、图片索引和主题样式到本机 runtime，补充尺寸、位置和绑定，
并移除遮住壁纸的桌面底色。背景根层保留原来的奶油色，桌面内容层使用透明背景。
传输校验成功后替换描述，重启设备生效，然后恢复 `.\start.ps1`。
重新应用整个奶油主题时，`apply_desktop_theme.py` 也会生成带边距的描述。
自定义主题若未提供该节点或安全边距，定时器自动跳过。

成品位图已随主题提供。需要重新导出时，在仓库根目录执行 `python tools/build_wallpaper_render.py`。
该转换会验证 RLE 解码后的所有像素与 RGB565 转换结果完全一致。

`DeviceModes.GetWeatherLayers` 的 `kind=wallpaper` 项可读取真实 LVGL 坐标及尺寸，供定时位移、边缘和息屏暂停验证使用。

完整实机检查（约 4 分钟，期间会打开时钟并让屏幕息屏 65 秒）：

```powershell
.venv\Scripts\python.exe tools/verify_wallpaper_shift.py --port COM5
```

仅更新渲染资源时，可加 `--quick` 验证一次真实定时位移；重复应用切换用 `tools/verify_wallpaper_switches.py` 检查。

## 实机记录（2026-10-22）

在 s3.17 上，同场景各 12 次同步整屏重绘，中位耗时从 297.4ms 变为 272.9ms，
输出条带从 15 变为 1。这里包含绘制与驱动提交开销，不能直接解释为纯 SPI 总线时间。
用户确认壁纸已明显改善、基本整张出现。
连续测量后的内部 RAM 剩余 107,783 字节，PSRAM 剩余 3,114,200 字节；
内存余量为当前短程场景采样，不保证所有应用组合下相同。

以下为 s3.16 的前次记录：

最终固件启动与图像解码日志正常。时钟、天气、额度各打开并返回两次，共 6 次切换通过；
实际壁纸描述为 RGB565、486×486、缩放系数 256（原生比例），另一次真实分钟位移检查通过，四周始终覆盖完整。
连续切换后的 PSRAM 剩余 3,576,096 字节，内部 RAM 剩余 48,223 字节。
前版相同定时逻辑已实测应用暂停、65 秒息屏暂停以及唤醒后重新计时恢复。
这些是短程设备检查，不等同于长期运行测试；详细运行报告保留在本机 runtime，不随仓库上传。
