# 迷宫加载内存修复（2026-11-17）

已部署固件 **s3.69** 和迷宫 **0.1.8**。本次修复针对GUI加载的大块连续分配风险，不能据此保证所有内存不足都已消除。

## 证据与选择

昨天的分段测试记录到11次迷宫GUI加载失败，关闭蓝牙也能复现。今天普通表盘与猫咪表盘的短轮次自然切换未复现，因此另做临时增大画布的受控测试，结束后用设备内树哈希核对恢复原界面文件。

1100×1100画布需要2,420,000字节连续空间。诊断实测当时PSRAM总空闲2,775,376字节，最大连续块只有1,474,560字节；分配失败回调记录2,420,000字节请求。可重建图片缓存清理后，最大块仍为1,474,560字节，重试仍失败。**总空闲容量不等于能分配的最大块，清缓存不足以解决此条件。** 这是受控压力证据，不将它冒充昨天720×720失败现场的完整根因追踪。

因此迷宫墙体缓存从一块720×720拆成四块360×360，缩略图保持76×76。最大像素分配从1,036,800降至259,200字节；总缓存仍为1,048,352字节。矩形在块边界裁剪并换算局部坐标，保持像素分辨率、颜色、连续镜头、碰撞、校准与随机关卡规则。移动只更新角色和相机，不重绘墙体。

原生端保留一次有界的图片缓存回收重试，持续失败继续上报；它不是本次修复的主要依据。新增最大连续PSRAM/内部堆、分配失败次数/大小/能力，以及画布重试诊断。失败回调仅写原子计数，不在回调中分配或打印；这些计数包含受控试验，不能直接等同用户可见错误数。

- 两轮每应用停留30秒：10次打开全部成功；另6轮蓝牙开启切换：30次打开全部成功。40次中包括8次迷宫启动，无启动失败；两组启动前最大连续PSRAM最低分别1,736,704和1,605,632字节。本轮新固件重启后的分配失败/画布重试计数均为0。
